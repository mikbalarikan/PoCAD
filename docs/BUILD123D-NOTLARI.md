# build123d ve OCCT tuzakları

Kaynak: oguz-atolye `library/BUILD123D-NOTES.md` @ca27b1b (MIT, PoCAD'e taşındı). Burada yalnız
`pocad.core` ve `pocad.result` testlerinin sabitlediği satırlar var; `measure` ve çizim satırları
o modüllerle birlikte gelecek. Tablo içeriği İngilizce bırakıldı ki kaynakla karşılaştırılabilsin.

Satırlar ilk olarak build123d 0.11.1 / OCCT 7.9.3'te görüldü. Sabitleyen testler PoCAD'de
build123d 0.13.0 / OCP 8.0.1.1 üzerinde yeşil; yani her tuzak bu sürümde de geçerli ya da
`pocad.core` hâlâ onu doğru karşılıyor. Bir sürüm yükseltmesinden sonra sabitleyen test kırılırsa
kütüphane değişmiş demektir: satırı yeniden oku, sonra aracı, testi ve bu dosyayı birlikte değiştir.
Kimlikler (R03, D-024, L-21 …) oguz-atolye'nin araştırma ve karar kayıtlarına aittir.

## Export and files

| Trap | Seen | What `pocad` does | Pinned by |
| `export_step()` always writes AP214. It has no schema argument, and it stamps a default header over the model (`APIHeaderSection_MakeHeader(0).Apply()`), which resets FILE_SCHEMA | R03 §1, R04 §1, past jobs | `pocad.core.write_step` is the one delivery writer (D-024) and asserts the schema by reading the header back | `test_core.py::test_trap_export_step_ignores_the_schema_static` |
| `Interface_Static.SetCVal_s("write.step.schema", ...)` returns False and does nothing until a STEP controller is initialised | R03 §1 | `write_step` initialises both STEP controllers before it sets anything, and checks every return value | the writer raises `ExportError` |
| The writer settings are process-wide statics that stick across exports. build123d's `export_step` sets `write.surfacecurve.mode` and `write.precision.mode` and leaves them set (with `write_pcurves=False` the next file loses its 54 parametric curves); any code can set `write.step.unit=INCH`, and a 40 mm edge is then written as 1.5748 while every round-trip check passes | REFERENCE-LIBRARY §3.5, the core review (2026-09-19) | `write_step` pins every static that changes the file (`STATICS`, OCCT's defaults, the angle unit included: with `step.angleunit.mode=Deg` a seam pcurve is written as 360 in a file that declares radians) for the write and restores what was there; it reads the length unit back and refuses anything but millimetres | `test_core.py::test_the_writer_pins_its_statics_and_restores_whatever_was_set`, `::test_the_unit_reader_sees_a_file_that_is_not_in_millimetres` |
| An enum static takes only its own words through `SetCVal` (`write.precision.mode` is `Min`, `Average`, `Max`, or `User`; "Greatest" returns False), while `SetIVal` also takes some indices that have no word (3 for `write.precision.mode`) | this repo, 2026-09-19 | `pinned()` sets enums by word and restores them by index, so an earlier value comes back even without a word; a static that does not exist is an `ExportError` naming it | `test_core.py::test_the_writer_pins_its_statics_and_restores_whatever_was_set` |
| The header *can* be set cleanly: `APIHeaderSection_MakeHeader(model)` on the writer's own model after `Transfer` is done and keeps AP242; it is `MakeHeader(0)` that resets the schema | this repo, 2026-09-19 | `write_step` writes the file name without a folder, the pinned timestamp, empty author, organisation, and authorisation, and the tool versions (DELIVERY.md §4) | `test_core.py::test_the_writer_gives_ap242_a_clean_header_and_the_same_bytes_twice` |
| The default header timestamp is the wall clock, so the same geometry gives different bytes | R04 §1 | `write_step` requires the caller to pin `timestamp`; two writes are byte-identical | same test |
| Part names change on the way through: `import_step` turns a space, `.`, `(` and `)` into `_`, and `_create_xde` writes non-ASCII names without the multibyte flag, so "GÖVDE" comes back double-encoded | the core review (2026-09-19) | `write_step` refuses a part label outside letters, digits, `_` and `-`, and a file name outside plain ASCII | `test_core.py::test_trap_part_names_change_on_a_round_trip`, `::test_the_writer_refuses_part_names_that_do_not_come_back` |
| `export_stl()` meshes with a *relative* deflection (`BRepMesh_IncrementalMesh(..., isRelative=True, ...)`), so its `tolerance` is not millimetres: at 0.01 a 300 mm tube is 0.7 mm off | build123d source, 2026-09-19 | `pocad.core.write_stl` meshes with an absolute chordal tolerance in mm | `test_core.py::test_trap_export_stl_tolerance_is_relative` |
| OCCT keeps the triangulation on the shape and reuses it: `export_stl` gave 756 triangles at every angular tolerance, and a mesh at the same linear tolerance with a coarser angle stays (924 triangles against 1008 fresh on a tube) | R04 §1, the core review | `write_stl` clears it with `BRepTools.Clean_s` before meshing | `test_core.py::test_trap_export_stl_reuses_a_cached_triangulation`, `::test_the_stl_writer_clears_a_stale_triangulation` |
| The mesher does not always keep to its tolerance: a loft meshed at 0.5 mm deviates 0.515 mm, a sphere at 0.01 mm and 0.1 rad 0.020 mm | the core review, this repo | `write_stl` measures the sagitta (13 points per triangle on every curved face) and returns it as a Result to gate; the centroid and edge midpoints alone read the loft as 0.476 | `test_core.py::test_the_sagitta_is_measured_because_the_mesher_can_miss_its_tolerance` |
| `GeomAPI_ProjectPointOnSurf` finds no point for some sample points on a cone (16 of 288 at 0.5 mm) | the core review | the sagitta projects with `ShapeAnalysis_Surface.NextValueOfUV` (exact on analytic surfaces, a search started from the triangle's own surface parameters on B-splines, where it is 8 times faster); it never missed, and a point it cannot project makes the result INCONCLUSIVE | `test_core.py::test_trap_global_projection_misses_points_on_a_cone` |
| OCCT numbers assembly occurrences (`NEXT_ASSEMBLY_USAGE_OCCURRENCE`) from a counter that lasts the whole process, so an assembly written twice gives different bytes | the second core review | `write_step` renumbers them 1, 2, 3 in file order | `test_core.py::test_an_assembly_written_twice_gives_the_same_bytes` |
| `import_step` reads with whatever `xstep.cascade.unit` the process holds: set to M, a 40 mm part reads as 0.04 | the second core review | `pocad.core.read_step` pins the reader statics (`READ_STATICS`, OCCT's defaults) and restores them | `test_core.py::test_the_reader_pins_its_statics` |
| `build123d.exporters3d._create_xde` is private API, used by the XCAF writer | R03 §6 | pinned by the lock file; a build123d upgrade reruns the core suite | the STEP writer tests |
| OCCT prints transfer statistics and the full output path through the default messenger's printers | this repo, 2026-09-19 | `pocad.core.shapes.quiet()` removes the printers while OCCT works and puts them back; file descriptors are left alone | `test_core.py::test_quiet_removes_the_printers_and_puts_them_back`, `::test_the_core_is_quiet` |

## Booleans and validity

| Trap | Seen | What `pocad` does | Pinned by |
| A boolean that removes everything returns an empty `Compound` with volume 0 and `is_valid` True; other failures return `None` or raise | R02, REFERENCE-LIBRARY §3.5 | count solids (`pocad.core.solid_count`); treat all three as INCONCLUSIVE, never 0 | `test_core.py::test_trap_an_empty_boolean_is_a_valid_compound_with_no_volume` |
| `BRepCheck_Analyzer.IsValid()` is true for a box missing a face and for an empty compound | R04 §1 | validity is three checks: one solid, a valid solid, no naked edges (`pocad.core.validity`) | `test_core.py::test_each_known_bad_part_fails_at_least_one_validity_check` |
| BRepCheck also passes a solid that overlaps itself (a helix sweep with a pitch under twice the tube radius) and an inside-out solid (volume −1000 mm³) | the core review | `brep_valid` adds two stages: every solid encloses a positive volume, then BOPAlgo's argument analyzer | `test_core.py::test_a_solid_that_overlaps_itself_fails_only_the_analyzer_stage`, `::test_an_inside_out_solid_fails_brep_valid` |
| The analyzer's curve-on-surface check compares each pcurve with its edge's own tolerance (1e-7 mm), so a sound thread, a library box, and a turned knob fail it by picometres after a STEP round trip | the second core review | a pcurve counts as a fault only when it is more than 1e-4 mm, or a millionth of the part's size, off its edge (the round trip moves them by 1.3e-4 mm on a thread 600 mm long); the distance and the limit are kept in `detail` | `test_core.py::test_a_threaded_part_stays_valid_through_a_step_round_trip`, `::test_the_pcurve_limit_grows_with_the_part` |
| The analyzer's self-interference check on an assembly reports parts that touch as `BOPAlgo_SelfIntersect` | the second core review | `brep_valid` checks each solid on its own; clashes between parts are `common_volume`'s question | `test_core.py::test_parts_that_touch_in_an_assembly_are_not_a_self_intersection` |
| The self-interference check runs for minutes on helical parts (42 s on a 24 mm thread, 25 minutes on a 32 mm one), and OCP cannot interrupt it: `Message_ProgressIndicator` has no constructor to subclass, and `Perform()` holds the GIL | the second core review | the analyzer runs in a worker process that is stopped when its budget (120 s) runs out: INCONCLUSIVE. Every answer echoes its request's id, an interrupted check stops the worker, and the worker dies with its parent (a Windows job object, Linux's parent-death signal) | `test_core.py::test_the_analyzer_stops_at_its_budget_and_the_next_check_runs`, `::test_an_answer_to_another_request_is_refused`, `::test_the_analyzer_worker_dies_with_its_parent` |
| `BOPAlgo_ArgumentAnalyzer` checks nothing until its modes are switched on: every mode defaults to False, and `HasFaulty()` is then always False | the core review | `brep_valid` switches on the modes that find defects in one shape (`BOP_MODES`) | `test_core.py::test_trap_the_argument_analyzer_checks_nothing_until_its_modes_are_on` |
| A STEP round trip rebuilds a self-intersecting profile (a bow tie) into a solid BRepCheck accepts; its lobes cancel to zero volume | this repo, 2026-09-19 | the positive-volume stage of `brep_valid` fails it | `test_core.py::test_self_intersections_still_fail_after_a_step_round_trip` |
| BOPAlgo's self-interference check fails (`BOPAlgo_AlertIntersectionFailed`, reported as `BOPAlgo_OperationAborted`) on faces extruded from Bézier curves, which build123d's `Text` draws; after a STEP round trip they are B-splines and the check runs | this repo, 2026-09-19 | `brep_valid` is INCONCLUSIVE, never a pass; the checks run on the re-imported STEP (PLAYBOOK D5); the fillet ladder rejects such a rung, so fillet before embossing text | `test_core.py::test_trap_the_self_interference_check_fails_on_bezier_glyphs_until_a_step_round_trip` |
| A degenerate edge (a sphere's pole, a cone's apex, a drill point's tip) belongs to one face, so a plain count calls it naked | the core review | `naked_edges` skips degenerate edges | `test_core.py::test_degenerate_edges_are_not_naked` |
| OCP's `BRepAlgoAPI_Common` exposes only `IsDone()`; `HasErrors()` and `HasWarnings()` are not bound | this repo, 2026-09-19 | `pocad.core.common_volume` checks `IsDone()`, treats a null result as INCONCLUSIVE, and turns any exception into INCONCLUSIVE | `test_core.py::test_trap_occp_boolean_has_no_error_flag` |
| A boolean on an unsound solid finishes with a confident wrong number: 0 mm³ between a self-overlapping sweep and a block inside its coils, 800 mm³ for 200 against an inside-out box | the core review | `common_volume` checks every solid that takes part (`brep_valid`, `naked_edges`) and is INCONCLUSIVE on an unsound one | `test_core.py::test_common_volume_refuses_an_unsound_solid_instead_of_a_wrong_number` |
| A boolean against a multi-solid compound measured a connector band 3.38 mm short | REFERENCE-LIBRARY §3.5 | `common_volume` works solid by solid with a bounding-box prefilter | `test_core.py::test_common_volume_works_solid_by_solid` |
| Touching solids share no volume, so contact reads 0 | REFERENCE-LIBRARY §3.5, R04 §1 | `common_volume` reports 0 for touching solids; engaged area needs a probe depth (L-22, `pocad.measure` (later)) | `test_core.py::test_common_volume_is_exact_and_touching_is_zero` |
| `Compound(children=...)` re-parents its inputs and can invalidate built parts: a part inside an assembly no longer transfers on its own ("the XCAF transfer failed") | REFERENCE-LIBRARY §3.5, the second core review | build the parts first; `write_step` refuses a part that has a parent and says why; write the assembly, or build the part again for its own file | `test_core.py::test_a_part_inside_an_assembly_is_refused_with_its_reason` |
